# 第一阶段续建评审记录

本文件记录接手开发后每个交付门（Stage Gate）的产品经理与技术总监评审。评审对象是
[`docs/product/product-manager-review.md`](../product/product-manager-review.md) 冻结的 P0 与验收口径，
以及 [`docs/architecture/technical-director-review.md`](../architecture/technical-director-review.md)
的架构与安全边界。交接清单见 [`docs/handoff/claude-handoff-2026-08-27.md`](../handoff/claude-handoff-2026-08-27.md)。

评审规则：

- 只有可重复执行、有输出证据的结果才算通过。页面存在、代码路径预留、本地沙盒成功都不算。
- 任何一方提出的问题必须落到具体门（本门修复 / 指定后续门 / 明确列入外部依赖阻塞）。
- 需要外部账号、商业授权或澳洲专业人士复核的门槛，不由本记录签核。

同门修复的缺陷：

1. **`GET /v1/projects/:projectId` 在项目含文件时返回 500。** `FileRecord.byteSize` 是 BigInt 列，
   `JSON.stringify` 无法序列化。已确认为真实缺陷：回退修复后重跑验收，18 条中 3 条失败，
   服务端日志为 `TypeError: Do not know how to serialize a BigInt`。修复后该接口同时不再返回
   `storageKey`，符合数据边界中“不把对象 key 当授权”的规则。
2. **PowerShell 脚本缺少 UTF-8 BOM。** Windows PowerShell 5.1 按 ANSI 读取，中文字符串会破坏解析，
   `.\scripts\start-local.ps1` 在 5.1 下直接语法报错。五个脚本已统一加 BOM。
3. **`APP_ORIGIN` 缺少 `http://127.0.0.1:53004`。** Flutter Web 预览调用本地 API 会被 CORS 拒绝。已补。

同门补齐的权限模型缺口（为 M2 的云文件删除 UI 做准备）：

4. `FileRecord.uploadedById` 与迁移 `20260827120000_file_uploader`；`DELETE /v1/files/:fileId`
   按冻结角色规则执行：所有者删除任何文件、可协作成员只能删除自己上传的文件、仅查看成员不能删除。

### 技术总监评审

**结论：通过。**

- **接受** `configureApp` 抽取：验收跑在与部署一致的 HTTP 管道上，避免出现“测试通过但生产管道不同”的假绿。
- **接受** BigInt 修复方式：在服务层显式转换并收窄 `select`，与 `files.service` 既有约定一致，
  优于全局修改 `BigInt.prototype`——后者会让未来任何新接口静默改变类型而不被发现。
- **接受** 上传者字段与删除接口：此前 `FileRecord` 没有上传者，无法执行“不能删除他人文件”，
  这是权限模型缺口而不是 UI 缺口。删除接口先落库再删对象，对象清理失败会留下
  `file.object_delete_failed` 审计并返回可重试错误，不会出现“记录还在但字节已消失”的反向不一致。
- **拒绝** 在脚本中默认关闭 corepack 完整性校验。`scripts/lib/pnpm.ps1` 只在检测失败时报错并列出
  三种修复方式，其中跳过校验必须由操作者显式选择。供应链校验不因为本机方便而默认关闭。
- **记录** 迁移与 `db push` 的分工：本地脚本继续用 `prisma db push`；生产部署必须用
  `prisma migrate deploy`，`20260827120000_file_uploader` 已按初始迁移的格式补齐。
- **记录** 验收数据清理：套件用一次性随机邮箱，结束时按邮箱级联删除账号；文件对象在
  隔离区→clean 拷贝和删除测试中被清理，MinIO 不留残留对象。
- **遗留到 P0-C：** 验收未覆盖 Cognito 校验路径、令牌刷新与多设备。
- **遗留到 P0-G：** 开发扫描模拟仍未替换为独立扫描 Worker；`DEV_AUTO_SCAN` 只在非生产可用，
  但生产替换尚未开始。

同门修复的缺陷：

1. **“创建安全分享入口”静默失败。** 分享面板的 `ListTile` 在 `Navigator.pop(context)` 之后，
   把**面板自己的** `BuildContext` 传给后续流程。该 context 随路由卸载，`context.mounted` 变为 false，
   于是创建流程直接 return：既不创建入口，也不显示错误。已改为使用项目页的 context。
   回归测试 `apps/mobile/test/secure_share_flow_test.dart` 在修复前失败（未发出任何请求）、修复后通过。
2. **“安全入口已创建”对话框无法关闭。** 只有“复制访问码”（不关闭）和“发送链接”（关闭并调起系统分享）
   两个动作，用户复制访问码后没有退出路径。已补“完成”。

### 技术总监评审

**结论：通过。**

- **接受** 三个页签一律直接读服务端、不写入本机项目状态的做法。撤销分享、降权成员和删除文件之后，
  本机缓存会让用户误判当前权限；这里的正确性优先于渲染速度。
- **接受** `_RemoteSection` 把“加载 / 失败可重试 / 空状态”统一成一个骨架，并且**失败显示为失败**，
  不退化成看起来正常的空列表——这正是交接文档禁止的“页面存在即完成”反模式。
- **接受** 刷新失败不再抛回调用方：否则“删除已成功但刷新失败”会被错报成“删除失败”，
  用户会重复执行破坏性操作。
- **接受** 下载云文件时校验 SHA-256：不一致即丢弃，且不覆盖本机原件。这条对应残余风险表里的
  “不允许静默损坏”。
- **接受** 为测试注入 `ApiClient` 工厂：此前所有服务端调用都在方法内部 `new`，客户端逻辑完全无法测试。
  现在 5 条云文件用例和 1 条分享流程回归都跑在 `MockClient` 上，不需要真实网络。
- **记录** 缺陷 1 的类别：**弹出层关闭后继续使用其 BuildContext**。这类问题不会被 analyze 发现，
  也不会报错，只会静默不执行。已在同类位置检查：材料项详情面板已正确使用 `sheetContext`，
  只有分享面板存在该问题。
- **要求并已修正：** `DELETE /v1/files/:fileId` 最初先删数据库记录再删对象。评审要求反过来：
  记录先消失、对象清理再失败的话，会留下用户看不见、也无法重试的残留字节，而用户已经被告知文件已删除。
  这与“删除必须是真实删除”的隐私门槛冲突。现在改为**先删对象、成功后才删记录**；
  对象删除失败时记录保留、返回可重试错误，`DeleteObject` 对不存在的 key 幂等，重试安全。
- **遗留：** `refreshCloudFileStatuses` 每次都拉取整个项目详情（含清单与审计事件）来读文件列表。
  文件规模变大后应改为独立的 `GET /projects/:id/files`；当前 P0 规模下可接受。
- **遗留到 P0-D 剩余项：** multipart 直传仍在 API 内存中承载最多 50 MB，生产应优先走预签名直传。
