# 第一阶段 UI 设计签核

**状态：已形成可运行设计并通过首轮视觉验收**  
**范围：Flutter iOS/Android 客户端、无 App 安全分享页、内容审核后台**  
**日期：2026-08-27**

## 1. 设计方向

产品处理的是高压力、长周期且包含敏感材料的任务。视觉不采用“政府门户蓝”、高饱和增长组件或游戏化进度，而使用安静、可信、可回溯的工作空间语言：深墨绿代表控制与安全，桉树绿代表完成动作，浅薄荷代表已核实信息，暖白与砂岩色降低长时间阅读负担。

主要原则：

- 先讲清状态，再让用户操作；“待核实”“仅本机”“只读”“不可撤回”等风险状态进入主要界面，不埋在条款里。
- 新闻与项目分开：资讯回答“发生了什么”，项目回答“我整理到哪里”，不能把模板包装成个人资格建议。
- 所有文档操作先显示兼容等级，默认保存副本；不把“已保存”用于可能损坏原件的场景。
- 访客可以完成第一件事，不用先交邮箱；账号价值用于恢复、云同步、安全链接和协作。
- 重要颜色不只承担语义，同时配文字、图标和状态标签，满足色觉差异与无障碍需要。

移动端基于 Material 3，但保留 iOS/Android 的系统文件选择、系统分享、权限和订阅行为。圆角采用 12/16/22 三档，正文最小 14sp，交互目标不小于 44×44。正文中文优先，英文只用于签证代码、司法辖区代码和运营语境。

## 3. 移动端信息架构

底部五个一级入口保持稳定：

1. **资讯**：今日重点、最新官方信息、官方来源与更新时间。
2. **变更**：前后差异、发现/核实状态、来源跳转和更正记录。
3. **项目**：SA 190、SA 491 或空白项目；清单、五段状态、提醒、文件、备份和分享。
4. **工具**：PDF、DOCX 的兼容预检、编辑、保存副本和导出。
5. **我的**：本机/账号状态、逐项目云同步、订阅、导出、账号删除、隐私与支持。

首屏不展示复杂统计，而依次回答：“今天要留意什么”“下一步做什么”“最新官方信息是什么”。项目详情把完成度、材料状态和本机/云端边界放在同一视线内。

## 4. 关键交互

- 创建项目：默认 SA 190，可切换 SA 491/空白；创建前明确“模板不代表完整或适用”。
- 状态推进：单击材料项按“未准备 → 准备中 → 已准备 → 已发送 → 已确认”循环；这些是用户工作状态，不代表政府确认。
- 加密备份：导出前要求至少 10 字符口令并二次确认；AES-256-GCM 加密，错误口令或篡改必须拒绝恢复。
- 云同步：账号建立与文件上传分开；项目首次开启云文件需显式同意。
- 分享：直接系统分享明确“发出后不可撤回”；安全入口默认 7 天、访问码、禁止下载；协作需登录并接受权限。
- 政策发布：一般变化可标记“自动发现、待核实”；重大/重要变化在后台没有“绕过审核直接发布”的路径。
- 文档：PDF 与简单 DOCX 显示支持级别；旧 DOC、宏、受保护或复杂版式只读/转换副本/外部打开。

## 5. 后台设计

审核后台只处理公开内容，不提供用户材料浏览器。桌面布局采用“队列 + 证据详情”双栏：左侧按重要性和等待时间排序，右侧同时显示上一版本、当前版本、来源、发现时间、人工摘要和发布护栏。核实、误报和更正均保留状态；后台密钥只存在当前会话，不写入浏览器持久存储。

- 小屏 iPhone、常见 Android、iPad/折叠屏的真实设备布局与软键盘测试。
- Apryse/ONLYOFFICE 真机 POC 后，用真实工具栏与失败态替换当前兼容入口；不能先冻结一个 SDK 无法实现的编辑器 UI。
- App Store/Google Play 截图不得暗示政府官方身份，也不能展示真实护照、银行、健康或家庭材料。
- 正式隐私政策、服务条款、支持方式和账号删除页在公司主体及处理者清单确认后再定稿。
