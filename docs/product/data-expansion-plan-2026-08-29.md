# 数据扩张方案（2026-08-29 实测）

## 先纠正一个数字

「31 条」不是「全澳两年的政策」。那是 **`migration.sa.gov.au/news` 一个页面的全部内容**——
一个州、一个新闻栏目，而且政策和活动混在一起（我筛出 18 条政策）。

我们当时只监控 10 个来源：8 个南澳页面 + 2 个联邦法条。所以量少不是澳洲政策少，
是我们只看了一个角落。

## 今天实测：哪些拿得到，哪些拿不到

| 来源 | 状态 | 实测量 |
| --- | --- | --- |
| **联邦法规注册库 API** `api.prod.legislation.gov.au` | ✅ robots 只禁 `/assets/`，声明 Crawl-delay 10s（我们已遵守） | **含 "Migration" 的条目 2453 条**，含 "Skilled" 81 条，最早可回溯到 1901 年 |
| 南澳 `migration.sa.gov.au` | ✅ 已接入 | 31 条（2024-07 → 2026-07），已入库 |
| 昆士兰 `migration.qld.gov.au` | ✅ robots 404（等于全允许），页面正常 | 疑似新闻链接 25 个，页面年份 2021–2026 |
| 新南威尔士 `nsw.gov.au` | ✅ robots 允许（标准 Drupal 规则） | 需要找对列表页 URL |
| 西澳 `wa.gov.au` | ✅ robots 允许 | 需要找对列表页 URL |
| 维州 `liveinmelbourne.vic.gov.au` | ❌ **robots.txt 本身 403** | 拿不到 |
| 塔州 `migration.tas.gov.au` | ❌ robots.txt 403 | 拿不到 |
| 北领地 `theterritory.com.au` | ❌ robots.txt 403 | 拿不到 |
| 首都领地 `act.gov.au` | ❌ robots.txt 403 | 拿不到 |
| 联邦内政部 `homeaffairs.gov.au` | ❌ 403（早前已确认） | 拿不到 |

**关于那四个 403 的准确说法**：不是「robots 禁止我们」，是**它们的 robots.txt 本身被边缘拦下**，
我们读不到规则。读不到就按最保守处理不抓——这是我们自己的规矩，不是对方明确的禁令。
和内政部是同一种情况。我们不做 UA 伪装、无头浏览器或 IP 轮换去绕。

**结论**：量是有的，2453 比 31 高两个数量级。主要在联邦法规库，其次是三个还能抓的州。

## 但真正的瓶颈不是抓取，是编辑

2453 条法规的标题长这样：`Migration Amendment (Class of Persons) Instrument 2024/12`。
把它们原样倒进一个面向中文用户的 App，比现在的 31 条更糟——用户看到的是一堆看不懂的
英文法律条目。

价值在**挑出与技术移民相关的那部分，并写成人话**。而每条发布都要中文标题和摘要
（`assertChineseEditorialCopy` 是硬闸门）。我这一轮手写 18 条已经是单次的合理上限。

所以扩张方案必须回答「摘要怎么产出」，否则抓得越多，后台积压越多，App 里能看的
反而不变。三种做法：

1. **纯人工**——现状，不超过每次 20 条，扩张后必然堵死。
2. **模型起草 + 人工核准**——和现有的人工闸门天然契合：机器出中文草稿，你在后台看一眼再发。
   这是唯一能跟上 2453 条的做法。
3. **结构化数据不写摘要**——见下一节，对邀请数据尤其适用。

## 邀请数据应该是结构化数据，不是新闻

你提到「每年每个月的邀请名单、数量、对应的州」。这类内容**不该做成新闻条目**。

现在 SA 的 6 条「Invitations issued」新闻，每条摘要只能写「本月数据已公布，详见官方表格」——
因为真正的内容是一张按 ANZSCO 职业大类分列 190/491 邀请人数的表。用户想知道的是
「我的职业这几个月邀请了多少人、趋势如何」，一条条翻新闻是最差的呈现方式。

建议单独建模：

```
InvitationRound
  jurisdiction   AU-SA / AU-QLD / ...
  programYear    2025-26
  roundMonth     2026-05
  visaSubclass   190 / 491
  anzscoGroup    "25 Health Professionals"
  invitationCount
  sourceUrl      官方原文
```

App 里做一个「邀请数据」页：选职业大类 + 签证类别，看月度趋势。这比 12 条
「本月数据已公布」有用得多，而且**不需要写任何中文摘要**——数字本身就是内容，
不涉及翻译和编辑判断。

## 兴趣订阅：已经建好七成

你要的「选择 491/186 → 相关政策自动提醒」，服务端已经有了：

- `NotificationPreference`：`jurisdictions[]` + `tags[]` + `importantOnly`
- `content.service.ts` 在变更被核实发布时，会按辖区和标签筛出匹配用户，写入 `NotificationOutbox`
- App 端已经在同步 `/notification-preferences`（GET + PATCH）

**缺的三处**：

1. **只有政策变更会触发，新闻发布不触发。** 这次回填的 18 条政策发布后，一个人也不会收到提醒。
2. **没有投递。** `POST /notifications/claim` 接口在，但**没有任何东西调用它**——
   消息进了 outbox 就躺着。需要一个投递 worker（推送 / 邮件）。
3. **标签体系不统一。** 现在标签是采集时按关键词拼的（`190`/`491`/`南澳`/`Other news`），
   要支持「关注 186」得先有稳定的标签词表。

## 加拿大 / 美国：这是换产品，不是补数据

我的看法是**先不做**，理由不是工作量：

- 澳洲这边还没挖完。联邦 2453 条 + 三个可抓的州，够做很久。
- 每加一个国家，「什么算移民建议」的合规红线要重新划一遍。澳洲这条线（Migration Act
  s.276 注册移民代理制度）我们已经研究过并写进了产品规则；美国、加拿大是另一套，
  而且比澳洲更严。
- 产品现在整个框架是围绕「南澳 190/491 州担保」建的——清单模板、职业清单、邀请数据。
  这些概念在加拿大（Express Entry / PNP）和美国（EB 类 / 排期表）都不直接对应。

如果目标是「数据要多」，答案在联邦法规库，不在别的国家。

## 后台上公网：可以做，但先解决登录

现在后台是回环 + SSH 隧道 + 一个共享密钥填进输入框。**这套东西不能直接搬到公网**——
后台能发布政策内容，密钥泄露等于别人可以向你的用户推送假政策。

要上公网需要：

1. **真正的登录**，不是共享密钥。复用已有的内测访问码机制（逐邮箱绑定 + scrypt + 失败锁定），
   再加 TOTP 二次验证。
2. **限流**。nginx 的限流区已经建好，加一个后台登录的区即可。
3. **审计**。谁在什么时候发布/撤下了哪条，现在 `AuditEvent` 模型有，但后台操作没有写入。
4. 保留回环入口作为兜底。

做完这三条，放在 `admin.migration-companion.…` 子域名下是安全的。**在那之前不要上公网。**

至于「App 端更好写」——审核后台和 App 是两拨人用的，不建议合并。App 里放审核入口意味着
审核权限要进用户体系，那是更大的攻击面。

## 建议的执行顺序

1. **邀请数据结构化**（新模型 + 采集 + App 页面）——不需要写摘要，见效最快，直接回答
   「我的职业这个月邀请了多少」。
2. **接入 QLD / NSW / WA**——三个还能抓的州，每个一套列表解析。
3. **联邦法规库接入 + 模型起草摘要**——量最大，但必须先解决摘要产出。
4. **通知投递 worker + 新闻发布触发**——把已经建好的七成接通。
5. **后台登录改造后上子域名。**
6. 加拿大/美国：等前五项跑顺、且澳洲用户量验证了模式再谈。

## 执行结果（2026-08-30）

### 数据量

| | 之前 | 现在 |
| --- | --- | --- |
| 条目 | 31 | **78** |
| 来源 | 南澳一个州 | 南澳 31、昆士兰 12、西澳 10、NSW 4、**联邦法规 21** |
| 跨度 | 2024-07 → 2026-07 | **2019-07 → 2026-07** |

联邦法规是按两层筛出来的（2019 年起 + 仍然有效 + 标题命中技术移民词表），
从约 999 条可达条目里选出 21 条。里面有几条是真正关键的：

- `LIN 19/210: Pool and Pass Marks for General Skilled Migration`——**打分通过线**
- `Migration (ANZSCO Definition) Specification 2024`——职业分类适用版本
- `Migration (English Language Requirements for Subclass 485)`
- `LIN 19/219: Occupations for Subclass 494 Visas`

### 拿不到的仍然拿不到

维州、塔州、北领地、首都领地、联邦内政部——**robots.txt 本身返回 403**。
我们读不到规则就不抓，也不做 UA 伪装 / 无头浏览器 / IP 轮换。这一条没有变。

### 摘要产出

模型起草 + 校验层 + 人工发布。校验层拦下的东西证明了它的必要：一次跑 26 条时，
**模型编造了两个邀请人数（9224、6540），原文里根本没有**，另一条写出了「建议申请」。
这两条要是直接发布，用户看到的就是虚构数据和一句移民建议。

### 邀请数据

按你的决定**不建新表**，保持为资讯条目，App 内浏览器看原文。

### 加拿大 / 美国

按你的决定暂不做，集中在澳洲。
