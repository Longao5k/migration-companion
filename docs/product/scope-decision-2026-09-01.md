# 产品范围与内容审核决策（2026-09-01）

**决策人：** 产品所有者  
**状态：** 生效，覆盖此前文档中与本决策冲突的“第一阶段只做 SA 190/491”条款。

## 1. 第一阶段的真实边界

- **资讯：** 覆盖全澳洲，且不局限于 190/491；可服务个人申请人的全部移民类型都属于候选范围。
- **首发市场：** 南澳仍是获客、运营验证和本机材料模板的起点，但不是资讯来源或签证类别过滤器。
- **材料模板：** 继续按已有证据逐类扩展。资讯范围扩大不等于把 SA 模板机械复制到其他州或签证。
- **后续国家：** 澳洲验证完成后再进入热门移民国家；每个国家单独完成来源、法律边界、隐私与产品术语评审。

## 2. 自动审核是默认路径

一个人不能逐条审核全澳洲资讯。内容生产应以自动化完成大多数低风险条目，只把冲突或高风险条目交给人工：

1. 仅从登记的官方/可信来源获取原文与证据快照，不绕过 robots、访问控制或站点封锁。
2. AI 生成中英文标题、摘要、分类和标签；数字、日期、法规编号及引文必须回指原文证据。
3. 使用确定性校验检查空字段、语言、建议性措辞、无证据数字、时间与来源一致性。
4. 使用独立复核步骤检查摘要是否被原文支持。起草与复核不得把同一次模型回答当作两票。
5. **只有低风险且全部检查一致的条目才可自动发布。** 审计记录必须保留模型/规则版本、证据、置信度和发布原因。
6. 以下情况必须进入人工队列：证据冲突、模型分歧、重大政策影响、法律解释、个案建议风险、数字无法逐项对齐、来源撤回/更正、低置信度或结构解析不完整。

人工后台的角色因此从“逐条重写所有资讯”改为“处理异常、冲突、更正与抽样质检”。自动发布仍需支持一键撤下、更正留痕与随机抽检，不能成为无审计的直发通道。

## 3. 不变的法律与商店边界

- 产品提供公开信息与材料组织工具，不判断个人资格、不推荐路径、不代填答案或递交。
- AI 摘要必须明确是信息摘要，不得伪装成政府原文或注册移民代理意见。
- 抓不到的站点不通过伪装 UA、绕过访问控制、住宅代理或无头浏览器规避限制。
- App Store / Google Play 发布前仍需完成澳洲移民法律、版权、隐私、订阅和商店披露的专业复核。

## 4. 产品所有者授权 Agent 最终复核（2026-09-06）

产品所有者不承担模型摘要的逐条复核。进入异常队列的资讯由 Agent 使用已配置的摘要 API
重新起草、由不同模型家族对完整官方摘录至少复核三轮，并由 Agent 对争议逐条作最终判断：

- 可由原文客观判定的问题（数字错列、遗漏适用条件、双语不一致、模型误报）由 Agent 直接修正；
- 每条发布前必须通过当前证据指纹、确定性内容校验和双语数字校验；证据在复核期间变化则整批预检失败；
- Agent 的修正理由、模型、轮数和最终处置写入审计；镜像新闻稿可归档为参考资料，不重复发布；
- 只有原文自身含糊、来源相互冲突、需要法律意见或涉及个案判断时，才交还产品所有者决定。

这项授权不会放宽第 3 节的法律边界，也不允许 Agent 把模型生成内容标记为人工编辑稿。
